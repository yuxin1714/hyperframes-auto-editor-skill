# HyperFrames Auto Editor

Make editorial decisions before authoring HyperFrames. Preserve the user's topic, approved creative direction, and requested quality.

## Three-stage collaboration

1. **Confirm requirements.** Reuse project settings and prior answers; ask missing consequential choices together.
2. **Develop and approve the complete plan.** Actually review references, design the script and visual treatment, resolve feasibility, then present one coherent proposal.
3. **Produce and verify.** After approval, execute autonomously, fix issues within scope, and deliver the reviewed file for acceptance.

Use [pipeline.md](references/pipeline.md) as the execution sequence. Read [topic-to-delivery.md](references/topic-to-delivery.md) for intake details and reference-led or imaginative concept development; it expands these stages, not a second workflow.

## Approval boundary

Before proposal approval, source inventory, transcription, frame extraction, analysis, and planning are allowed. Do not synthesize voice, generate media, materially author the composition, render, or spend credits.

Record the actual approval in APPROVAL_RECORD.md. Prior approval covers technical and quality fixes. Seek revised approval only for changes to script meaning, core claim, target duration by more than 10%, visual format, digital-human use, provider, budget, or deliverables.

## Authenticity and completion

Product behavior, transformations, measured results, testimonials, and real events need real evidence. Generated media may explain or illustrate; it cannot fabricate proof. Keep source provenance internally.

An access failure is a route failure, not proof that suitable material is unavailable. Try other available browser, public-demo, official, app-store, local-capture, or user-material routes. Never silently substitute fake UI, placeholders, or lower-quality media. A simulation needs explicit disclosure in the approved plan.

Technical checks and creative review are separate. Resolve blocking findings before calling a file final; report unverified checks and concrete remaining gaps honestly. Do not promise an error-free result solely because tooling reports no errors.

## Sustainable maintenance

Keep incidents and project preferences local. Promote only approved reusable operating rules, not failure narratives. Update the narrowest reference, remove duplicates, validate the skill, inspect the diff, and synchronize only skill files to its configured repository.

Invoke from any conversation as $hyperframes-auto-editor. Other devices update through scripts/install-or-update.ps1; media, accounts, knowledge bases, and environment paths remain device/project-specific.
