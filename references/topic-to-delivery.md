# 自动剪辑：需求确认、方案审核、制作验收

三个阶段：① 用户提供主题 / 素材＋主题 / 纯文案，执行者询问并确认需求；② 设计完整脚本、画面和制作方案，用户审核，不通过则修改再审；③ 方案通过后实施、自检，交给用户验收，不通过则修订。这是三阶段协作，不限制为三条消息。需求尚未确认时不先做完整方案。

## 0. 项目基础配置（首次建立，后续复用）

在项目 PROJECT.md 保存产品资料位置、品牌资源、目标受众/平台/语言、期望时长范围、人物使用规则、固定音色、素材路径、视觉偏好与通过/不通过的参考、交付格式、可用服务及费用上限。密钥只通过安全配置读取，不写入文档或仓库。

已有明确答案不重复问；尚未明确的关键偏好在第一阶段集中询问，给出推荐但不以默认值代替确认。账户接入、必要真实素材、支付授权等不能凭空推定。先检查现有配置，缺少不可替代项时集中说明一次。

每台设备分别验证依赖、资产路径和服务访问；代码仓库同步不等于素材库、账户和运行环境已经同步。

## 第一阶段：接收输入并确认需求

先快速阅读输入、检查素材元数据与代表帧，识别意图与明显限制；此时不做全片深度分析或完整脚本。

- 仅主题：确认所属产品/项目和可用素材，再确认制作需求。
- 素材＋主题：说明素材适合的表现方式，但不把素材形式直接当成成片类型。
- 纯文案：确认原文保留或允许改写的范围、是否配音以及产品关联，不擅自改变原意。

集中给出一份简短需求确认单，已知项列出核对，未知项提供推荐和少量可选方向：

| 确认项 | 内容 |
|---|---|
| 视频类型 | 录屏教程、旁白讲解、产品广告、混剪等，可有主辅类型 |
| 用途与平台 | 发布平台、受众、讲解/品牌/转化等目的 |
| 时长 | 目标区间及上限，不仅是“以内” |
| 比例与分辨率 | 分别确认，例如9:16、1080×1920；说明源素材清晰度限制 |
| 风格 | 实际库内选项或用户参考；库为空时给出推荐方向，不虚构库条目 |
| 文案与声音 | 语言、保留/改写范围、原声/AI配音/无旁白、沿用或选择音色 |
| 人物与素材 | 真人/数字人/无人脸、必用和禁用素材、是否允许补充生成素材 |
| 其他条件 | 涉及时确认预算、服务、交付期限，不询问无关技术参数 |

等待缺失关键项的回答；用户明确“其余你定”后可自主决定该范围。用户一次回复已覆盖全部信息时直接进入第二阶段，不重复要求确认。把结果写入 EDITORIAL_BRIEF.md 的 Confirmed requirements；需求确认只授权设计方案，不授权制作。

## 第二阶段：完整方案设计与审核

### 对标驱动的创意迁移（用户提供参考时，先于完整脚本）

先实际观看参考并核实声音/文案，再做对标分析。记录链接、标题/主题、可确认时长、实际观看范围和带时间点的证据。完整观看、部分观看、只有文案、用户描述、访问失败必须明确区分；未完整观看不能交付全片结构分析，不能用通用经验或用户描述冒充观看发现。访问失败时继续尝试其他实际可用渠道；合理替代途径验证后仍有缺口，再报告具体阻塞，参考依赖的结论保持待定。

逐条提炼三层内容：

1. 内容：原片到底回答什么问题、比较什么对象、使用什么生活尺度、提供什么价值、最终兑现什么。
2. 吸引机制：反差、成本换算、熟悉事物类比、身份认同、清单发现、悬念等如何由具体内容产生。没有传播数据时称潜在吸引机制，不宣称已证明爆款原因。
3. 表现：按时间点记录信息顺序、揭晓位置、旁白/音乐作用、动画与录屏分工、镜头停留及转场动作。不要只给“高级科技风”这样的泛化标签。

然后做“原片机制 → 当前主题的新问题 → 产品关联 → 可展示证据 → 可迁移视觉”的映射。保留有效的叙事逻辑，重新设计当前产品的表达，不能只换产品名、配色或用通用功能介绍替代原片主题。用户举例作为思考方向，不视为指定唯一方案或已证实事实。

为用户准备少量实质不同的方案（通常2–3个），每个写清：参考依据、核心问题、开头、展开与结果、画面/动效节奏、真实素材需求、事实待核项、推荐理由。区别应体现在比较维度、观众问题或叙事机制，而非只换首句。用户已授权选定某方向时直接深化，不增加强制选角关卡。

涉及价格/成本时核实套餐、日期、换算口径与比较条件；涉及耐久度时没有测试则只能作为明确夸张的视觉隐喻；跨应用使用须逐一有兼容/操作证据，不推导成所有应用通用。允许先提出待验证概念，但不得写成确定旁白或伪造对比结果。

#### 两种创意模式

对标驱动方案至少覆盖下列模式之一；当用户希望看到多种思路时，通常各给一个，再补一个最有价值的变体。

**模式A：逐段同构复刻。** 建立原片beat表，将每个段落的内容功能、叙述句式、信息揭晓顺序、动画行为、镜头时长、转场职责和结尾动作逐一映射到当前产品。允许一比一保留结构和节奏逻辑，每一格写出“原片作用 → 当前产品替换内容 → 所需证据/资产”。素材使用遵循用户授权和项目要求，内部保留来源。关键段落没有产品事实或素材承接时标明缺口，不能声称已经完成复刻。

**模式B：高想象力概念。** 先抛开产品功能列表，从主题寻找更大的比较对象、文化语境或可视化事件，例如熟悉消费、硬件损耗、时间或注意力的反常换算。要求第一眼能看懂冲突、画面能连续发展、有超出常规产品广告的记忆物。产品在故事因果成立后才出现，作为自然动作或答案，而不是创意起点。

高想象力不等于捏造事实：可使用明确的荒诞设定、拟人化或视觉隐喻；数字比较、产品兼容、用户经历和性能结论仍须核实或清楚标为概念。优先参考`tki-content-creation`的故事优先、具体细节、延迟揭晓、反转与软植入方法；当用户明确要求产品主导的直效广告时不强制套用70–85%故事比例。

#### 创意发散检查

- 至少一条方案的核心名词不能来自产品功能表；如果所有方案都只是“更快打字、少打字、语音转文字”，继续发散。
- 方案应回答一个观众愿意参与判断的问题，例如“哪个更伤键盘”“一天到底值多少”“哪些任务还值得打字”，而非只让观众接受一句品牌结论。
- 夸张概念必须给出可制作的画面链条，不接受只有标题而没有事件发展的点子。
- 产品出现前，故事自身也应具备继续观看的理由；出现后要在因果上解决前面建立的问题。
- 每个方案标注其主要风险：事实核验、素材缺口、理解门槛、品牌距离或制作复杂度。

### 1. 拆解主题

先读取工作区要求、知识库索引与相关条目、产品资料及既有用户反馈。形成：目标观众、具体情境、矛盾/问题、视频必须回答的问题、看完得到的价值，以及产品在其中承担的作用。

主题不能直接变成一句口号。内部比较少量不同切口，选择与主题、观众和证据最匹配的一种，说明理由。素材先做可行性盘点，但不让一段已有音频替代主题策划。

### 2. 产品事实与证据匹配

建立简短的“文案主张 → 产品资料出处 → 可见演示证据 → 表达边界”映射，放在 EDITORIAL_BRIEF.md 或 SCRIPT.md。区分官方描述、实测结果、策略推断。参考中的夸张、固定时间比例、平台经验不是通用硬规则。

录屏与资料冲突时，当前演示只能证明实际发生的行为。不得用模拟界面补造产品结果。第一人称必须有明确的表达主体，不能替数字人编造客户体验。

### 3. 写完整脚本并自审

主题驱动的短视频策划优先使用可用的 viral-short-form；开头有独立打磨需要时使用 viral-hooks；再按主要平台选择 viral-tiktok-content 或 viral-instagram-reels 的相关规则。故事植入型项目可改用 tki-content-creation。只读实际需要的技能，不机械叠加全部技能。缺少某技能时可用等价编辑判断，但明确替代，不虚报调用。

产出 SCRIPT.md：精确口播原文、供中文用户审核的中文含义、屏幕标题与字幕策略、各段叙事任务、主张证据和预估时长。以完整叙事决定目标区间；词数/语速只用于预估，最终以生成音频实测。已有配音只有在用户要求保留且支持主题时才作为约束。

自审：是否回答主题、开头是否兑现、每段是否推进、产品是否有必要、语言是否自然可读、主张是否可证、所需画面是否能获得。删掉空泛卖点与无作用段落，保留必要操作和阅读时间。自审不通过不进入方案确认。

### 4. 类型路由与素材分析

按第一阶段确认的类型应用 video-types.md，按需增加辅类型；发现不可行时说明替代方向，不自行改变核心呈现形式：

| 类型 | 编排中心 | 主要画面 | 特别验收点 |
|---|---|---|---|
| 口播/旁白讲解 | 完整论点与表达节奏 | 真人已有素材，或获批 AI 旁白搭配录屏/图解 | 不剪断意思；无人脸也能理解 |
| 软件录屏教程 | 问题、操作、结果 | 清晰内录、局部聚焦、步骤标注 | 操作连续、控件与结果可读 |
| 产品广告 | 场景、机制、证据、收益 | 真实产品证据与获批解释性素材 | 卖点可证、品牌清晰、结果兑现 |
| 混剪/叙事短片 | 情绪或信息的推进 | 授权镜头、图像、图解 | 有发展而非堆素材；声画与方向连贯 |
| 访谈精剪 | 自包含观点 | 原始访谈与必要补充画面 | 不改变原意、说话人与上下文准确 |

批量检查元数据、代表帧、声音和文字；重要操作精查到实际时间段。分析结果缓存，素材变化才重算。配音和原视频对白必须转写或实际试听核实，不能由波形推断内容。

### 5. 逐段视觉编排与资源闭合

把脚本映射到 VISUAL_BEAT_MAP.json：每段说什么、观众应看懂什么、使用哪段真实素材、何时聚焦、何种示意动效、音效如何配合。无声看画面与仅听旁白都要能理解主要信息。

从共享库分别选整体风格和局部动效；记录 ID、状态和理由。风格至少明确构图、字体、配色、字幕、界面处理、运动节奏和声音方向。优先少量叙事相关组件；图像生成、视频生成、数字人仅在有具体作用且可用时启用。

把缺口分为：已有可用、可自动获取、可在获批后制作、缺少不可替代输入。生成只能解释或补充气氛，不能补造真实产品证明。

方案确认前检验：素材读取权限、必要产品操作/录制能力、配音及转写服务配置、选中组件实现工作量、生成服务与预算、最终音画检查能力。配置存在只算 configured；成功测试才算 tested。未授权付费调用不能作为试连借口。

不可替代输入缺失时，优先提出仍能忠实回答主题的可执行方案；不能通过改成无关主题或降低承诺的视觉标准掩盖问题。无可行路线时，在确认方案前集中列出最少缺口，不承诺已经可以三步完成。

### 6. 用户确认一份完整方案

常规任务呈现一个推荐方案；用户要求多方案或对标迁移时，提供少量实质不同的方案并标明推荐。每个方案均须交代可行性与必要资源，选定方向再锁定唯一制作版本。PRODUCTION_PROPOSAL.md 必须包含：

- 主题解释、目标人群、内容类型、平台和明确时长区间；
- 完整逐句脚本及中文含义；
- 分段时间、实际画面、来源范围、关键动效、声音与观众获得的信息；
- 风格说明和已有参考图/库内预览；没有预览时明确仅文字描述，不冒充已制作效果；
- 配音音色、生成素材/服务、预算上限、重试范围和已批准的替代路线；
- 证据边界、已知素材限制、具体交付文件；
- 可观察的验收标准及剩余阻塞（存在阻塞则不得标为可直接实施）。

确认前只做分析、转写、抽帧与文档规划，不生成新媒体或制作视频。保存用户实际确认的方案版本与范围。不要要求用户逐镜选动效或选择技术工具。

用户不通过方案时，按反馈修改并展示更新后的完整有效方案，简述变化，继续等待审核。“修改某处”不等于批准实施，除非用户明确说改完直接制作。需求变化同步更新需求记录。只有明确通过制作方案后才进入第三阶段。

## 第三阶段：实施、自检与视频验收

### 7. 确认后自主生产

按批准脚本生成配音，实测时长并核对漏读、发音、语气；在获批区间内微调停顿、阅读留白和切点。必要时在已批准预算内重生成，不偷偷删减主题。

获取已获授权的素材，制作选中图解/动效；先核实关键媒体在最小组合中的渲染，再完成完整粗剪，最后统一排版、字幕、动效、音效和混音。使用 HyperFrames/CLI 与 FFmpeg 等实际可用工具；脚本依赖和组件版本固定。

完整时间线应覆盖真实镜头与生成段落。将所选共享实现复制至项目并锁定版本，不直接引用会变化的库文件。预览是内部检查，不要求用户增加一次审片。

### 8. 内部验收与自主修正

按 quality-gates.md 完成技术与创意两类检查。至少检查：主题与脚本兑现、真实操作证据、音频与字幕一致、手机尺寸可读性、素材/动效风格协调、声音不抢旁白、镜头节奏、目标时长、输出格式、黑帧/遮挡/断音。

检查实际导出文件，连续看听评估节奏；抽帧用于布局和细节，两者不能相互替代。检查工具或感知能力不可用时如实记录，不能把未检查标成通过。

发现问题在已批准范围内自行修正；每轮针对具体发现复核，不无限重做。无进展或预算将超限时停止盲目重试，使用已批准替代路线；没有等效路线则集中报告阻塞。改变核心主张、脚本意义、人物形式、服务/预算或超出批准时长仍须重新确认。三阶段协作允许必要往返，不隐瞒实施阻塞。

### 9. 交付供用户验收

提供成片、简短的方案兑现说明和真实限制；默认保留可编辑工程与字幕文件，封面/平台发布文案按批准方案交付。相同技术规格可共用视频母版，平台差异涉及内容或布局时才另出版本。不自动发布。

用户给验收反馈后，在原方案范围内直接修订；新增主题或重大方向变化才返回方案确认。记录通过/不通过的具体视觉与内容偏好用于下一次选型，不将“技术通过”当成用户审美认可。

### 10. 持续优化与完成标准

按 continuous-improvement.md 更新实际操作要求；项目反馈留在项目内。流程只保留可执行改进，不堆积原因分析。共享组件仅在明确授权且有渲染证据时升级状态。

流程文档通过不代表自动化通过。用代表性主题实跑验证：需求是否先确认、方案是否明确通过、是否出现未提前说明的补材料/补配音、结果是否满足已确认标准、用户是否接受。至少一次完整运行通过才能称该项目该类型已打通；不能据此宣称所有视频类型通用验收通过。
