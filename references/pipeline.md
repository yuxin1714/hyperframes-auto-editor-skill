# Execution Pipeline

This is one production sequence within the three-stage collaboration. References supply criteria, not extra approval rounds or repeated analysis.

## Stage 1: Confirm requirements

Read workspace instructions, relevant knowledge, and PROJECT.md. Reuse known answers. Quickly inventory supplied media and confirm missing type, platform/audience, duration range and maximum, ratio/resolution, language/voice, style, brand role, authenticity, and delivery choices together. Read topic-to-delivery.md for the intake form.

Keep this pass cheap: metadata and representative frames, not full-source deep analysis. Requirement confirmation authorizes planning only.

## Stage 2: Design one reviewable plan

### Reference and topic interpretation

When references are supplied, actually review each complete reference, including audio and all carousel pages. Record observed range and timestamp evidence. Extract topic premise, hook mechanism, narrative sequence, visual mechanism, pacing, and transferable relationship to the new subject. Partial viewing supports only partial findings; thumbnails, descriptions, and URLs do not establish full structure. Follow alternative access routes before reporting a specific gap.

Develop the complete narrative demanded by the topic. Short supplied media or narration must not silently reduce its argument, duration, proof, or payoff. Reconcile the story with evidence feasibility before locking it. Use the creative modes in topic-to-delivery.md when relevant.

Offer one recommended direction by default. Offer a few substantively different concepts when requested or useful; once a direction is selected, deepen it without an additional mandatory selection gate.

### One evidence and feasibility pass

Create MEDIA_MANIFEST.json; preserve originals and cache analysis by source fingerprint. Batch metadata, transcript, quality, and representative-frame analysis. Deeply inspect only candidate or uncertain ranges: what happens, actual action/result timing, legibility, and the claim proved. Audition or transcribe narration; waveforms do not establish words.

Choose the primary mode and relevant platform/script skills. Build SCRIPT.md and EDITORIAL_BRIEF.md. Map each material spoken beat to its claim/takeaway, concrete visual object/action, proof/explanation/context role, and evidence source timestamp. A product name or generic interface is not semantic coverage.

During the same pass, resolve hook, identity, core proof, payoff, CTA, media gaps, tool availability, and budget. Record unresolved gaps in ASSET_GAPS.md with severity and feasible remedies. Actual product transformations require real input/action/output. Do not acquire expensive generated assets before approval.

Select exact source ranges and record EDIT_DECISION.json. Score uncertain candidate alternatives when it changes selection; do not repeatedly score already selected unchanged clips. Validate source bounds and timing once per decision revision.

### Visual plan and proposal

Create VISUAL_BEAT_MAP.json, DESIGN.md, and STORYBOARD.md using the validated decision as the timing authority. Define recurring source stages, phone-scale evidence readability, caption zones, visual hierarchy, semantic motion, and audio. Inspect shared style/motion indexes once where applicable; record selected implementations and availability. Library size is not a quality metric.

Present PRODUCTION_PROPOSAL.md with exact script, hook, timed shots and source ranges, framing/motion, voice/music, generated assets/provider/cost, proof boundaries, gaps/fallbacks, observable acceptance criteria, and deliverables. Record approval according to SKILL.md; do not add per-shot or per-tool approvals.

The records above are a compact shared plan: cross-reference script and clip IDs instead of copying full scripts, timing, and source reasoning into every document.

## Stage 3: Produce, review, deliver

### Build

If the environment is unverified, test one real-media/audio/cut combination after approval; reuse working paths and versions thereafter. Generate approved voice and assets, verify actual narration, and update authoritative timing within scope.

Assemble the complete story first. Before animation, review every scene's most complete static hero frame at delivery size: visual center, vertical balance, media readability, alignment, line breaks, intentional negative space, safe zones, and absence of empty panels, placeholders, production notes, or redundant copy.

Use consistent, deliberate aspect ratio, dimensions, crop, and placement for recurring media formats. Do not blindly prescribe cover or contain: preserve essential proof and integrate any letterboxing intentionally.

Then add captions and semantic motion. Follow semantic-visualization.md for active-media coordinates and exact word/action timing. Snapshot selected shared implementation versions locally. Follow the required HyperFrames authoring/CLI skills.

### Review and repair

Use quality-gates.md as the single checklist. Start with a draft encode and static/structural checks; fix concrete findings before a high-quality render. Review the full narrative with audio where supported, full-duration contact sheet, high-frequency hook frames, all boundaries, semantic overlays, captions, and CTA.

After a local visual fix, recheck that range and its adjacent boundaries. After global layout, timing, caption, or audio changes, rerun the relevant full check. Reuse unaffected analysis. Stop repeating diagnostics or renders that yield no new evidence; change method or name the remaining gap.

### Delivery and learning

Render the requested final formats after the draft passes. Verify actual delivered files and metadata; identify exact file revision and accepted limitations in QC_REPORT.md. Confirm copied files match the validated encode using hashes when copies are made. Do not publish automatically.

Fix acceptance feedback within approved scope directly. Keep incident findings in PROJECT.md; promote only approved reusable corrections using continuous-improvement.md. Audience performance remains unknown until publication evidence exists.
